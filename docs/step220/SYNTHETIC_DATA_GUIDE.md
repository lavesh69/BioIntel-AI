# Synthetic Data Guide

Synthetic projects use `synthetic_demo_output` origin and visible `SYNTHETIC DEMO DATA` notices. Configure module, scenario, size, seed, and bounded controls; generated tables include origin columns, ground truth, expected QC, recommendations, and a hashed manifest.

Step220 canonical adapters send every clean/failure fixture through the production analysis registry. Synthetic datasets, runs, evidence, validations, and reports remain isolated from real projects. Mixed-origin evaluation requires explicit controls and cannot promote synthetic evidence to real validation.
