## Main improvements

1. Added a shared evidence-readiness engine with weighted data-quality, study-design, provenance, independent-validation, and reproducibility controls.
2. Added domain-specific critical evidence requirements for the weakest scientific areas, including flow cytometry, metabolomics, spatial/pathology, docking/MD, pharmacogenomics, population genetics, structural variation, genome-editing safety, proteogenomics, glycomics, immunoinformatics, antibody engineering, and single-cell trajectory workflows.
3. Expanded all 80 registered scientific profiles to complete six-stage contracts: input QC, study design, domain analysis, specialist execution, reproducibility, and independent validation.
4. Added the Scientific Readiness Command Center for portfolio-wide engine, reference, blocker, and evidence-template review.
5. Hardened Flow Cytometry with explicit control-manifest validation, single-stain compensation derivation, gate hierarchy auditing, instrument-QC review, and independent reviewer release gating.
6. Added fail-closed handling for synthetic/demo evidence and explicit release blockers when required evidence is absent.
7. Repaired analytics aggregation so bounded dashboards preserve complete portfolio totals instead of silently dropping low-volume modules.
8. Restored brand/theme compatibility while keeping the BioIntel Signature brand theme and the safe legacy Executive preference fallback distinct.
9. Repaired navigation catalogue governance, shared design-system coverage, featured-module limits, and semantic visual baseline integrity.
10. Hardened the Windows installer with path-safe absolute invocation, offline bootstrap and post-install self-test contracts, and aligned desktop/mobile/deployment version surfaces.

## Validation boundary

The repository is verified to the automated software and scientific-readiness controls included in this package. This is not a claim of clinical diagnostic approval, GxP qualification, regulatory certification, prospective wet-lab validation, or independent external scientific validation. Those require qualified external datasets, domain reviewers, physical Windows qualification, and applicable regulatory processes.
